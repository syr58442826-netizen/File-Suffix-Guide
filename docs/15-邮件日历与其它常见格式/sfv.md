# .sfv 文件后缀详解

## 1. 文件定义 & 用途

SFV（Simple File Verification，简单文件校验）是一种用于验证文件完整性的轻量级校验文件格式。它使用 CRC32 校验算法来检测文件是否损坏或被篡改。SFV 文件本身是纯文本格式，里面记录了每个文件的文件名和对应的 CRC32 校验值。

SFV 格式的核心特点：
- **简单轻量**：格式简单，文件体积小，生成和校验速度快
- **CRC32 算法**：使用 CRC32 循环冗余校验，计算速度快
- **纯文本格式**：可以用记事本直接打开查看
- **场景特定**：在动漫、影视、破解软件发布圈非常流行
- **安全性低**：CRC32 不是密码学哈希，只能检测意外损坏，不能防篡改
- **多文件支持**：一个 SFV 文件可以校验多个文件

## 2. 适用场景

- **发布资源校验**：动漫组、影视组发布资源时附带 SFV 文件，方便下载者检查完整性
- **多文件校验**：一次性校验大量文件（如一个系列的剧集）
- **传输完整性检查**：检查文件在复制、传输过程中是否损坏
- **归档验证**：长期归档的文件定期验证是否完好
- **破解/汉化圈传统**：早年破解软件、汉化补丁发布的标配

## 4. 如何编辑、如何导出

### SFV 文件格式说明

SFV 文件是纯文本，格式非常简单：
```
; 这是注释行（以分号开头）
filename.rar 1A2B3C4D
another_file.rar 5E6F7A8B
```

每一行的格式：`文件名 + 空格 + 8位十六进制CRC32值`

### 如何校验 SFV

**使用 QuickSFV（Windows，最方便）：**
1. 安装 QuickSFV 后，SFV 文件会关联
2. 直接双击 .sfv 文件
3. QuickSFV 自动校验同目录下的所有文件
4. 显示结果：绿色 = 完好，红色 = 损坏/缺失

**使用命令行（Linux/Mac）：**
```bash
# 安装 cksfv
sudo apt install cksfv   # Debian/Ubuntu
brew install cksfv       # macOS

# 校验
cksfv -f files.sfv

# 或使用 crc32 命令手动对比
crc32 filename.rar
```

**手动校验：**
1. 用记事本打开 SFV 文件，记下每个文件的 CRC32 值
2. 用工具计算实际文件的 CRC32 值
3. 逐个对比是否一致

### 如何生成 SFV 文件

**使用 QuickSFV（Windows）：**
1. 选中要生成校验的文件
2. 右键 → QuickSFV → Create SFV
3. 自动在同目录生成 .sfv 文件

**使用命令行（Linux/Mac）：**
```bash
# 生成 SFV（当前目录所有文件）
cksfv *.rar > files.sfv

# 递归生成
cksfv -r . > files.sfv
```

**批量生成：**
- 可以选中多个文件夹批量生成
- 也可以用脚本对整个目录树生成 SFV

### SFV vs MD5 vs SHA256 怎么选？

| 对比项 | SFV (CRC32) | MD5 | SHA-256 |
|--------|-------------|-----|---------|
| 算法类型 | CRC（校验和） | 密码学哈希 | 密码学哈希 |
| 长度 | 32 位（8字符） | 128 位（32字符） | 256 位（64字符） |
| 计算速度 | 非常快 | 快 | 中等 |
| 防意外损坏 | 可以 | 可以 | 可以 |
| 防恶意篡改 | 不行 | 弱 | 强 |
| 适用场景 | 资源发布、快速校验 | 完整性校验 | 安全校验 |

## 5. 常见报错与解决

### 问题 1：SFV 校验失败，提示文件损坏

**原因：** 文件在下载或传输过程中损坏，或文件不完整。

**解决方法：**
1. 检查是否所有文件都下载完成（特别是分卷压缩文件）
2. 重新下载损坏的文件（只需重新下载出错的那个，不用全下）
3. 如果是 BT 下载，让下载软件重新检查完整性并修复
4. 如果是从网盘下载的，可能是网盘传输错误，换个下载方式试试

### 问题 2：双击 SFV 文件没反应或打不开

**原因：** 没有安装 SFV 校验软件，或文件关联丢失。

**解决方法：**
1. 下载安装 QuickSFV 或类似工具
2. 安装后 SFV 文件会自动关联
3. 也可以右键 → 打开方式 → 选择 QuickSFV
4. 只是查看内容的话，用记事本打开就行

### 问题 3：文件名含中文时 SFV 校验出错

**原因：** SFV 格式对非 ASCII 字符支持不好，编码不匹配会导致找不到文件。

**解决方法：**
1. 确保 SFV 文件和系统使用相同的编码
2. 使用较新的 SFV 工具（支持 UTF-8）
3. 避免文件名包含中文和特殊字符
4. 如果只是个别文件有问题，可以手动重命名匹配

### 问题 4：SFV 和 MD5 有什么区别？我该用哪个？

**解答：**
- **SFV**：速度快、文件小，但安全性低。适合快速检查文件是否损坏（如下载完动漫、电影）。
- **MD5**：速度稍慢，安全性比 SFV 高。适合软件发布、系统镜像等对安全性要求稍高的场景。
- **SHA256**：最安全，速度最慢。适合安全要求高的场景（如加密货币、数字签名）。

日常下载资源校验用 SFV 就够了；软件和系统镜像用 MD5 或 SHA256。

## 💡 小知识

SFV 格式虽然简单，但它在互联网文化中留下了独特的印记。如果你经历过 2000 年代的 BT 下载和论坛资源分享时代，一定对 SFV 文件不陌生——那时候下载任何动漫、电影、游戏破解版，压缩包旁边几乎都有一个 .sfv 文件。

为什么 SFV 在那个圈子特别流行呢？因为 CRC32 计算非常快，对于动辄几十上百个分卷的 RAR 压缩包来说，用 SFV 校验速度比 MD5 快得多。而且 SFV 格式极其简单，任何人都能用记事本看懂和修改。

不过 SFV 有个致命弱点——它只能检测"意外损坏"，不能防止"恶意篡改"。因为 CRC32 不是密码学哈希，攻击者可以造出两个 CRC32 值相同但内容不同的文件。所以 SFV 只适合校验下载是否完整，绝对不能用来验证文件的安全性和来源。

有趣的是，很多人把 SFV 文件里的 CRC32 值直接嵌到了文件名里，比如 `[动漫字幕组]某番剧第01话[720P][1A2B3C4D].mp4`——那个方括号里的 8 位十六进制数就是 CRC32 值。这样你甚至不需要 SFV 文件，直接看文件名就能校验。这是当年资源分享圈的一种"民间标准"。
